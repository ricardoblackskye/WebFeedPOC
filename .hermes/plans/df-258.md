# Plan: DF Test for issue 742

Story: #258
Issue: [#258](https://github.com/ricardoblackskye/webfeedpoc/issues/258)

## Goal

Add one italic line of copy — 'Built by the Dark Factory - by the Developer Agent' — to the home page only. The home page is the index route of the '/' shell, implemented by src/pages/HomePage.jsx, so the new line is appended to that component's returned fragment as a scoped `<footer> wrapping an <em> element (the <em>` supplies the italics from the user-agent stylesheet, so no CSS file changes). src/App.jsx already renders a global .app-footer, but App is the shell for every route (products/:slug, category/:categoryName, architecture, orders, about, order-confirmation, releasenotes), so the copy must NOT go there. A new colocated Vitest suite, src/pages/HomePage.test.jsx, pins the exact copy, the italics, and the fact that the line survives the empty/loading product states. No other file is touched.

## Approach

Route ownership decides the target file. src/main.jsx mounts <Route path="/" element={`<App/>`}> with <Route index element={`<HomePage/>`}/>, and src/entry-server.jsx prerenders the identical table (path "/" -> App, index -> HomePage), so src/pages/HomePage.jsx is the only component whose output is exclusive to the home page. src/App.jsx (role=shell in the evidence, it renders `<Outlet/> plus the existing global <footer className="app-footer">) is rendered on every route, so adding the line to that footer would leak the copy onto product, category, architecture, orders, about and release-notes pages and break the story's 'No other changes' constraint. The change is therefore a single insertion in src/pages/HomePage.jsx: after the {selectedProduct && <ProductModal .../>} block, still inside the top-level fragment, add <footer className="home-footer"><em>Built by the Dark Factory - by the Developer Agent</em></footer>. The <em> element renders italic by default in every browser and in the jsdom used by Vitest, so no stylesheet (src/index.css, src/App.css) is edited and the diff stays inside one source file. The new copy sits outside every conditional block in HomePage (the loading, error, no-products and no-results branches), so it must be visible in all product states; that is asserted, not assumed. Testing follows the repository's existing colocated pattern (src/components/Cart.test.jsx sits beside src/components/Cart.jsx) with src/pages/HomePage.test.jsx. Because HomePage calls useOutletContext(), useSearchParams() and <Helmet>, the suite renders it inside <HelmetProvider>` and a MemoryRouter whose layout route supplies the outlet context object ({ products: [], loading: false, error: null, categories: [], productCounts: { All: 0 }, addToCart: vi.fn() }); no provider stubs are mocked beyond that, so the test exercises the real component. TDD order: write the failing suite first (the copy is not in the DOM yet), run it to confirm the failure is 'unable to find text', add the one-line footer, re-run to green, then run the whole Vitest suite plus ESLint to prove nothing else moved.

**Objective:** Append an italic footer line with the exact copy 'Built by the Dark Factory - by the Developer Agent' to the fragment returned by src/pages/HomePage.jsx, proved by a new colocated Vitest suite, without changing any other file or any existing home-page output.

**Files:** `src/pages/HomePage.jsx`, `src/pages/HomePage.test.jsx`

**Steps:**

1. Create src/pages/HomePage.test.jsx following the colocated pattern used by src/components/Cart.test.jsx (Vitest globals describe/it/expect/vi, @testing-library/react render + screen).
2. Add a renderHomePage() helper that renders `<HelmetProvider><MemoryRouter initialEntries={['/']}><Routes>`<Route element={`<Outlet context={{ products: [], loading: false, error: null, categories: [], productCounts: { All: 0 }, addToCart: vi.fn() }} />`}><Route index element={`<HomePage />`} />`</Route></Routes></MemoryRouter></HelmetProvider>`; this supplies the outlet context, router params and Helmet context that HomePage's useOutletContext, useSearchParams and Helmet calls require.

Do not touch src/App.jsx's .app-footer, do not add CSS, and do not alter any existing element, conditional or prop.
9. Run: npx vitest run src/pages/HomePage.test.jsx — expected PASS (all five cases).
10. Run: npx vitest run — expected PASS for the whole suite (no regression in Cart, CategoryFilter, ImageModal, ProductList, Pagination, SortControls, StockIndicator, ProductCard, ProductModal, ProductPage suites).
11. Run: npm run lint — expected clean (no new ESLint findings).
