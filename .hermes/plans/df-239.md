# Plan: Dark Factory Test Issue

Story: #239
Issue: [#239](https://github.com/ricardoblackskye/webfeedpoc/issues/239)

## Goal

Add one italic attribution line — the exact string 'Built by the Dark Factory - by the Developer Agent' — to the bottom of the home page route only. The change lives in src/pages/HomePage.jsx (the component bound to the index route '/'), implemented as an `<em> inside a <footer>` at the end of the returned fragment, with a new colocated Vitest/RTL test proving both the copy and the italics. No other component, route, style file, handler or data flow is touched.

## Approach

The home page is the route '/' and the evidence resolves that route to two files: src/App.jsx (role 'shell', which renders an `<Outlet/>` and is therefore mounted on every route) and src/pages/HomePage.jsx (role 'page', imported by src/entry-server.jsx as the index element of the '/' route). The story says the line belongs to the home page and that nothing else may change, so the line goes in src/pages/HomePage.jsx, not in the shell — putting it in App.jsx would leak it onto /products/:slug, /category/:categoryName, /about, /architecture and the order pages, which the story explicitly forbids. HomePage.jsx already owns all home-only markup (category filter, sort controls, product list, pagination, product modal), so a home-only footer is the same responsibility.

The implementation is a single presentational block appended to the existing returned fragment, immediately after the conditional `<ProductModal/> block: a <footer className="home-footer"> containing a <p> containing an <em> with the exact copy from the story (a plain ASCII hyphen, no dashes substituted). Italics come from the semantic <em>` element itself, so no CSS file is created or edited and the 'no other changes' constraint holds; the only new class name is a hook for future styling and is not required for the acceptance criteria. The markup stays inside the same <> ... </> fragment the component already returns, so it renders during both the client hydration pass and the server render used by scripts/prerender.mjs, with no new props, imports, state or effects.

Verification follows the repository's existing test convention (colocated *.test.jsx next to the component, Vitest + React Testing Library, assertions written as toBeDefined()/toBe() like src/components/Cart.test.jsx rather than jest-dom matchers). The new src/pages/HomePage.test.jsx mocks the two react-router-dom hooks HomePage consumes (useOutletContext, useSearchParams), the five child components it composes, Helmet and the structured-data helper, then renders HomePage with a one-product context and asserts three things: the exact string is present, the element carrying it is an `<em>` (the italics requirement), and the pre-existing home content still renders alongside it. The suite is written first and must fail before the markup is added. A second, non-code task gates the release: the full unit suite, ESLint and the production build must all pass with only the two files changed, which is how the 'no other changes' requirement is mechanically proven.

### 1. Add the italic Dark Factory attribution line to the home page footer

**Objective:** The index route renders the exact string 'Built by the Dark Factory - by the Developer Agent' inside an `<em>` element in a footer at the end of HomePage.jsx, proven by a new colocated React Testing Library test that fails before the markup exists and passes after.

**Files:** `src/pages/HomePage.jsx`, `src/pages/HomePage.test.jsx`

**Steps:**

1. Write the failing test. Create src/pages/HomePage.test.jsx colocated with src/pages/HomePage.jsx, following the convention already used by src/components/Cart.test.jsx (Vitest imports, RTL render/screen, toBeDefined()/toBe() assertions — do not assume jest-dom matchers are registered). Content:

```jsx
import { describe, it, expect, vi, beforeEach } from 'vitest'
import { render, screen } from '@testing-library/react'
import { useOutletContext, useSearchParams } from 'react-router-dom'
import HomePage from './HomePage'

vi.mock('react-router-dom', () => ({ useOutletContext: vi.fn(), useSearchParams: vi.fn() }))
vi.mock('../components/ProductList', () => ({ default: () => <div data-testid='product-list' /> }))
vi.mock('../components/ProductModal', () => ({ default: () => null }))
vi.mock('../components/CategoryFilter', () => ({ default: () => null }))
vi.mock('../components/SortControls', () => ({ default: () => null }))
vi.mock('../components/Pagination', () => ({ default: () => null }))
vi.mock('react-helmet-async', () => ({ Helmet: ({ children }) => <>{children}</> }))
vi.mock('../utils/structuredData', () => ({ generateItemListSchema: () => null }))

const ATTRIBUTION = 'Built by the Dark Factory - by the Developer Agent'

describe('HomePage footer attribution', () => {
  beforeEach(() => {
    useOutletContext.mockReturnValue({
      products: [{ id: '1', name: 'Vase', price: 10, category: 'Ceramics' }],
      loading: false,
      error: null,
      categories: ['Ceramics'],
      productCounts: { All: 1, Ceramics: 1 },
      addToCart: vi.fn(),
    })
    useSearchParams.mockReturnValue([new URLSearchParams(), vi.fn()])
  })

  it('renders the Dark Factory attribution line in the home page footer', () => {
    render(<HomePage />)
    expect(screen.getByText(ATTRIBUTION)).toBeDefined()
  })

  it('renders the attribution line inside an <em> element', () => {
    render(<HomePage />)
    expect(screen.getByText(ATTRIBUTION).tagName).toBe('EM')
  })

  it('leaves the existing home page content unchanged beside the new line', () => {
    render(<HomePage />)
    expect(screen.getByRole('heading', { name: /All Items/ })).toBeDefined()
    expect(screen.getByTestId('product-list')).toBeDefined()
  })
})
```

Note: getByText('…') matches only the `<em>, because RTL compares an element's own direct text nodes — the wrapping <p>/<footer> have no direct text child. The heading must be queried by role, because the <h2>` text is split by the sibling .product-count span.
2. Run: `npx vitest run src/pages/HomePage.test.jsx`. Expected: FAIL — 'Unable to find an element with the text: Built by the Dark Factory - by the Developer Agent'. If the file instead fails to import or the mocks do not resolve, fix the test before continuing; it must fail on the missing string, not on setup.

```jsx

          <em>Built by the Dark Factory - by the Developer Agent</em>

```

Copy the string exactly as written above (plain ASCII hyphen between 'Factory' and 'by', single spaces). Match the file's existing style: two-space indent, double quotes on JSX attributes, no semicolons, no trailing comma changes. Change nothing else — no new imports, no new props, no state, no existing class names, and no CSS file.
4. Run: `npx vitest run src/pages/HomePage.test.jsx`. Expected: PASS — 3 tests passed.
5. Commit: `git add src/pages/HomePage.jsx src/pages/HomePage.test.jsx && git commit -m "feat(home): add Dark Factory footer attribution line"`.

**Verification:** `npx vitest run src/pages/HomePage.test.jsx` reports 3 passing tests, and `git diff --stat HEAD~1` lists exactly src/pages/HomePage.jsx (a 5-line added footer block) and the new src/pages/HomePage.test.jsx — nothing else.

| `src/pages/HomePage.jsx` | modify | This file IS the home page: src/entry-server.jsx declares the route table and binds `<Route index element={<HomePage />} />` inside `<Route path="/" element={<App initialProducts={data.products} />}>`, so HomePage renders only on the '/' route.
