# Plan: Test for the Dark Factory (resume on approval bug)

Story: #235
Issue: [#235](https://github.com/ricardoblackskye/webfeedpoc/issues/235)

## Goal

Lock in the product-image lightbox behaviour on the product detail route: clicking a gallery thumbnail opens the image in a modal dialog sized to the image itself, clicking the image again closes it, and hovering the thumbnail shows a magnifier (zoom-in) cursor. ImageModal.jsx (the component that already owns the .image-modal-backdrop/.image-modal-content/.image-modal-image markup and the images/currentIndex/onClose/onNavigate/productName contract) gains click-to-close plus dialog semantics and a natural-size guarantee; ProductPage.jsx (the page mounted by ProductPageWrapper.jsx at products/:slug) gains the gallery trigger wiring and the modal placement; ProductPage.css gains the zoom-in cursor rule. No new dependencies, no routing or data-fetching changes.

## Approach

ImageModal.jsx already renders the full-size image markup (src/components/ImageModal.jsx: .image-modal-backdrop > .image-modal-content > button.image-modal-close + img.image-modal-image + .image-modal-nav) and ImageModal.test.jsx already covers the current-image-by-index, close-button and prev/next wrap-around cases. The story's three behaviours are therefore behavioural pins rather than new subsystems, and every one of them is proven by a vitest case in an already-existing, already-colocated suite.

1) "Clicking again closes the pop-up". Today the backdrop closes on click and the .image-modal-content wrapper calls stopPropagation, so a click on the picture does nothing. The plan adds onClick={onClose} to the `<img className='image-modal-image'>` element, leaving the wrapper's stopPropagation intact so clicks on the close button and the prev/next arrows keep their own behaviour and do not close the dialog. The modal backdrop also gains role='dialog', aria-modal='true' and aria-label={`${productName} image viewer`, matching the dialog pattern the repo already uses for the cart drawer in src/components/Cart.jsx, which makes the dialog queryable by role in tests instead of by CSS class.

2) "The same size as the image". The `<img>` keeps only src, alt and className='image-modal-image' - no width/height attributes and no inline style - so the browser paints it at its intrinsic size inside a content wrapper that is sized to the image; the test asserts exactly that (attribute and style absence plus the .image-modal-content ancestor), which is the mechanical, jsdom-observable contract behind "same size as the image". No stylesheet is allowed to add a width/max-width:100% rule to .image-modal-image; if the implementer adds any sizing rule while touching ProductPage.css, it must be max-width/max-height viewport clamping only, never upscaling of the image itself.

3) "Cursor changes to a magnifier". ProductPage.jsx wraps each gallery image in a <button type='button' className='product-image-trigger' aria-label={`View ${product.name} full size`}> so the click target is keyboard-reachable and has an accessible name, and ProductPage.css defines .product-image-trigger { padding: 0; border: none; background: none; cursor: zoom-in; }. Because vitest does not process CSS into jsdom, the cursor acceptance criterion is verified by two mechanical assertions in the same test: the trigger element carries the product-image-trigger class, and the text of src/components/ProductPage.css (read with node:fs and the file URL) matches a .product-image-trigger rule containing cursor: zoom-in.

State ownership: ProductPage keeps a single piece of local state, modalIndex (null = closed, number = open at that gallery index). The modal is rendered only when modalIndex !== null, it is passed the same images array the gallery maps over, onNavigate={setModalIndex} and onClose={() => setModalIndex(null)}. Triggers are only rendered when the product has at least one image, so ImageModal is never mounted with an empty images array (its safeIndex modulo would produce NaN). Navigation between images while the modal is open is unchanged from today's ImageModal behaviour; the feature intentionally does not add Escape-to-close or swipe gestures because the story does not ask for them.

Test-first order: the ImageModal behaviour tests are written and made to fail first (they fail because onClose is never called from an image click and because the backdrop has no dialog role); the ProductPage integration test is written next and fails because no element with the accessible name 'View ... full size' exists; the cursor test is written last and fails because neither the class nor the CSS rule exists. Each task ends with its own green suite and a commit, and the final task re-runs the whole vitest suite, eslint and tsc.

## Tasks

### 1. ImageModal: close on image click, dialog semantics, natural-size image

**Objective:** Modify src/components/ImageModal.jsx so a click on the modal image closes the dialog and the modal is exposed as role='dialog' with aria-modal='true', while the `<img class='image-modal-image'>` keeps only src/alt/className (no width, height or inline style) so it renders at the image's own size. Public contract is unchanged: images: string[], currentIndex: number, onClose: () => void, onNavigate: (index: number) => void, productName: string.

**Files:** `src/components/ImageModal.jsx`, `src/components/ImageModal.test.jsx`

**Steps:**

1. In src/components/ImageModal.test.jsx add `screen` to the existing `import { render, fireEvent } from '@testing-library/react'` line and append this failing test (it reuses the file's existing `images` fixture of three URLs):

it('closes the modal when the modal image is clicked again', () => {
  const onClose = vi.fn()
  const { container } = render(`<ImageModal images={images} currentIndex={0} onClose={onClose} onNavigate={() =>` {}} productName='Test' />)
  fireEvent.click(container.querySelector('.image-modal-image'))
  expect(onClose).toHaveBeenCalledOnce()
})
2. Run: npx vitest run src/components/ImageModal.test.jsx -t 'closes the modal when the modal image is clicked again'. Expected: FAIL - onClose is called 0 times, because the `<img>` has no handler and its parent .image-modal-content calls stopPropagation.
3. Implement in src/components/ImageModal.jsx: add `onClick={onClose}` to the existing `<img className='image-modal-image' src={images[safeIndex]} alt={productName} />` element. Keep `.image-modal-content`'s onClick={(e) => e.stopPropagation()} exactly as-is so clicks on the close button and the prev/next arrows do not close the dialog via the backdrop.
4. Run: npx vitest run src/components/ImageModal.test.jsx -t 'closes the modal when the modal image is clicked again'. Expected: PASS.
5. Add the second failing test to src/components/ImageModal.test.jsx:

it('renders the modal image at its natural size without forced width/height', () => {
  render(`<ImageModal images={images} currentIndex={1} onClose={() =>` {}} onNavigate={() => {}} productName='Test' />)
  const dialog = screen.getByRole('dialog')
  const img = dialog.querySelector('.image-modal-image')
  expect(img.getAttribute('src')).toBe(images[1])
  expect(img.hasAttribute('width')).toBe(false)
  expect(img.hasAttribute('height')).toBe(false)
  expect(img.getAttribute('style')).toBeNull()
  expect(img.closest('.image-modal-content')).not.toBeNull()
  expect(dialog.querySelector('.image-modal-backdrop')).toBeNull()
})
6. Run: npx vitest run src/components/ImageModal.test.jsx -t 'renders the modal image at its natural size without forced width/height'. Expected: FAIL on screen.getByRole('dialog') - the backdrop div currently has no role.
7. Implement in src/components/ImageModal.jsx: on the root `<div className='image-modal-backdrop' onClick={onClose}>` add role='dialog', aria-modal='true' and aria-label={`${productName} image viewer`}. Do not add width, height, style or any sizing class to the `<img>`, and do not add a width/max-width: 100% rule for .image-modal-image anywhere.
8. Run: npx vitest run src/components/ImageModal.test.jsx. Expected: PASS for all cases, including the two new ones and the pre-existing index/close-button/prev-next-wrap cases.
9. Commit:

git add src/components/ImageModal.jsx src/components/ImageModal.test.jsx
git commit -m 'feat: close image modal on image click and expose dialog semantics'

**Verification:** npx vitest run src/components/ImageModal.test.jsx - all tests pass, including 'closes the modal when the modal image is clicked again' and 'renders the modal image at its natural size without forced width/height', with the four pre-existing ImageModal cases still green.

### 3. Magnifier cursor on product images

**Objective:** Give the gallery trigger button in src/components/ProductPage.jsx the class `product-image-trigger` and add a `.product-image-trigger` rule with `cursor: zoom-in` to src/components/ProductPage.css so hovering a product image shows the magnifier cursor, proven by an assertion on the rendered element and on the stylesheet text.

**Files:** `src/components/ProductPage.css`, `src/components/ProductPage.jsx`, `src/components/ProductPage.test.jsx`

**Steps:**

1. In src/components/ProductPage.test.jsx add `import { readFileSync } from 'node:fs'` at the top and append this failing test (it reuses the fixture with at least two images from the previous task):

it('applies a zoom-in magnifier cursor to the product image', () => {
  render(`<ProductPage ...same props/fixture as the existing passing tests... />`)
  const trigger = screen.getAllByRole('button', { name: /view .* full size/i })[0]
  expect(trigger).toHaveClass('product-image-trigger')
  const css = readFileSync(new URL('./ProductPage.css', import.meta.url), 'utf-8')
  expect(css).toMatch(/\.product-image-trigger\s*\{[^}]*cursor:\s*zoom-in/)
})
2. Run: npx vitest run src/components/ProductPage.test.jsx -t 'applies a zoom-in magnifier cursor to the product image'. Expected: FAIL - the trigger button has no class yet (toHaveClass fails).
3. Implement in src/components/ProductPage.jsx: add className='product-image-trigger' to the gallery `<button>` created in the previous task, leaving its type, key, aria-label and onClick unchanged.
4. Implement in src/components/ProductPage.css: append the rule

.product-image-trigger {
  display: block;
  padding: 0;
  border: none;
  background: none;
  cursor: zoom-in;
}

Add nothing to .image-modal-image or .image-modal-content that scales the picture up or down; at most allow max-width/max-height viewport clamping.
5. Run: npx vitest run src/components/ProductPage.test.jsx -t 'applies a zoom-in magnifier cursor to the product image'. Expected: PASS.
6. Run the whole suite and the repo gates: npx vitest run && npm run lint && npm run typecheck. Expected: all green, no eslint or tsc errors introduced.
7. Commit:

git add src/components/ProductPage.jsx src/components/ProductPage.css src/components/ProductPage.test.jsx
git commit -m 'feat: show zoom-in cursor on product images'

**Verification:** npx vitest run src/components/ProductPage.test.jsx passes including 'applies a zoom-in magnifier cursor to the product image'; npx vitest run, npm run lint and npm run typecheck all complete with no failures.
