# Plan: Test issue for the Dark Factory issue #754

Story: #260
Issue: [#260](https://github.com/ricardoblackskye/webfeedpoc/issues/260)

## Goal

One additive presentational change. The home page ('/' in src/entry-server.jsx, served by src/pages/HomePage.jsx) renders its product grid by composing src/components/ProductList.jsx; that component gains exactly one extra element — a paragraph carrying the copy 'Built by the Dark Factory - by the Developer Agent' — and its co-located stylesheet src/components/ProductList.css gains exactly one declaration making that paragraph italic. No new files, components, props, hooks, routes, data fetches or schema changes; the site-wide shell footer in src/App.jsx is left untouched.

## Approach

The home page is the index route of the App shell: src/entry-server.jsx maps '/' to `<App> with <HomePage> as the index child, and src/pages/HomePage.jsx imports ProductList from '../components/ProductList' and renders <ProductList products={paginatedProducts} onAddToCart={addToCart} />. That import/render pair is the composition path by which the home page's content is produced, so the new footer line is added there: ProductList returns a React fragment whose first child is the existing markup byte-for-byte and whose last child is <p className="product-list-footer">Built by the Dark Factory - by the Developer Agent</p>`. The italic requirement is satisfied in the co-located stylesheet with a single rule, .product-list-footer { font-style: italic; }, following the repository's one-stylesheet-per-component convention (Cart.jsx/Cart.css, CategoryFilter.jsx/CategoryFilter.css). Nothing else is touched: no prop is added, no conditional rendering is introduced, no text elsewhere is reworded, and the shell footer in src/App.jsx is deliberately left alone because the story scopes the line to the home page. The work is done test-first in the existing Vitest suite src/components/ProductList.test.jsx — first a text-rendering assertion, then a stylesheet assertion that reads ProductList.css from disk with the fs.readFileSync + process.cwd() pattern already proven in src/components/CategoryFilter.test.jsx, and finally a regression guard that the existing product cards still render. Review focus for this change: (1) the copy must match the story character-for-character, including the plain hyphen and no trailing period; (2) the footer must not displace, wrap or re-key the existing product card markup; (3) the paragraph must actually be italic, which jsdom cannot compute, so the CSS declaration is asserted from disk rather than from a computed style; (4) the new element must not break the existing ProductList tests that render with an empty products array or a null onAddToCart; (5) if ProductList is also composed into the category route, the line will render there too — the plan keeps the change in one place rather than branching on route, because the story forbids other changes.

### 2. Style the footer line in italics and guard the rest of the page

**Objective:** Make the new footer paragraph italic via the co-located stylesheet, assert that declaration from disk, and add a regression guard proving no other home page content changed.

**Files:** `src/components/ProductList.css`, `src/components/ProductList.test.jsx`

**Steps:**

1. In src/components/ProductList.test.jsx, add at module scope (mirroring src/components/CategoryFilter.test.jsx): const cssText = readFileSync(path.resolve(process.cwd(), 'src/components/ProductList.css'), 'utf8'), importing readFileSync from 'node:fs' and path from 'node:path'.
2. Add the failing test: it('styles the footer line in italics via .product-list-footer', () => { const withoutComments = cssText.replace(/\/\*[\s\S]*?\*\//g, ' '); expect(withoutComments).toMatch(/\.product-list-footer\s*\{[^}]*font-style:\s*italic/i); })
3. Run: npx vitest run src/components/ProductList.test.jsx -t 'italics'. Expected: FAIL — no .product-list-footer rule with font-style: italic exists yet.
4. Append exactly one rule to src/components/ProductList.css: .product-list-footer { font-style: italic; } — no margin, colour, alignment or other declaration.
5. Run: npx vitest run src/components/ProductList.test.jsx -t 'italics'. Expected: PASS.
6. Add the regression guard: it('still renders every product card passed to it', () => { render(`<ProductList products={[{ id: '1', name: 'Alpha Item', price: 10 }, { id: '2', name: 'Beta Item', price: 20 }]} onAddToCart={vi.fn()} />`); expect(screen.getByText('Alpha Item')).toBeDefined(); expect(screen.getByText('Beta Item')).toBeDefined(); })
7. Run: npx vitest run src/components/ProductList.test.jsx. Expected: PASS — the two new tests plus all pre-existing tests, with no changes to any other component, page, route or stylesheet.
8. Commit: git add src/components/ProductList.css src/components/ProductList.test.jsx && git commit -m 'style: render home page footer line in italics'

**Verification:** npx vitest run src/components/ProductList.test.jsx reports all tests passed, including 'styles the footer line in italics via .product-list-footer' and 'still renders every product card passed to it'. git diff --stat shows only src/components/ProductList.jsx, src/components/ProductList.css and src/components/ProductList.test.jsx changed across both commits.
