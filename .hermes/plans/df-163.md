# Plan: Dark Factory Test Issue 3

Story: #163
Issue: [#163](https://github.com/ricardoblackskye/webfeedpoc/issues/163)

## Goal

Add a single new presentational element to the application's main page: a bold sub-heading that reads exactly 'Welcome to the site'. The change is implemented as one new colocated component (src/components/WelcomeHeading.jsx) plus its unit test, and a two-line integration into the existing main page component (src/components/ProductPage.jsx) with a matching assertion added to that component's existing test file. No dependencies are added, no styling system is introduced, and no other file or behavior is touched.

## Approach

The repo is a Vite + React (JSX) storefront whose page-level component is src/components/ProductPage.jsx (the only page-level component in the repository listing; it composes CategoryFilter, ProductList, SortControls and Pagination). The story asks for one bold sub-heading with fixed copy and explicitly says 'No other changes', so the work is deliberately minimal and strictly TDD.

Step one creates a tiny, dependency-free presentational component, `WelcomeHeading`, that renders `<h2 style={{ fontWeight: 'bold' }}>Welcome to the site</h2>`. An h2 is the correct semantic 'sub-heading' (the page's h1 remains the page title). Boldness is expressed as an inline style rather than a colocated CSS file because Vitest does not apply imported CSS in jsdom; an inline style is the only form of 'bold' that an automated test can actually assert via `toHaveStyle`. The copy string is hard-coded exactly as the story specifies, including capitalization and no trailing punctuation.

Step two adds one import and one JSX line to ProductPage so the heading renders as the first thing inside the page's root element, above the existing filter/list content, and adds a single assertion to the existing ProductPage test file (reusing that file's existing render setup / mocks). Nothing else in ProductPage changes, and no other component, CSS, config, or test file is modified.

Assumption / fallback: if the repository's real main page is composed in a top-level entry file that is not in the provided listing (e.g. src/App.jsx) and ProductPage turns out not to be the main page, the implementer should place the `<WelcomeHeading />` render at the top of that main page component instead of (or in addition to) ProductPage, and point the integration assertion at that file's test. The component, its test, the copy, and the boldness assertion are unchanged by that fallback.

Global constraints carried by every task: copy must be exactly `Welcome to the site`; the element must be bold; the element must be a sub-heading (h2), not the page title; no other files, styles, dependencies, or behaviors may change; the full existing test suite must remain green.

## Tasks

### 1. Create the bold 'Welcome to the site' sub-heading component

**Objective:** Introduce a new, self-contained presentational component `WelcomeHeading` that renders an h2 with the exact copy 'Welcome to the site' in bold, proven by a failing-then-passing unit test.

**Files:** `src/components/WelcomeHeading.test.jsx`, `src/components/WelcomeHeading.jsx`

**Steps:**

1. Create `src/components/WelcomeHeading.test.jsx` (this file does not exist yet). Match the import style and test setup already used by a sibling test such as `src/components/ProductList.test.jsx` (testing-library `render`/`screen`, vitest `describe`/`it`/`expect`, jest-dom matchers enabled). Add exactly these two cases: `it("renders a level-2 heading with the exact text 'Welcome to the site'", () => { render(<WelcomeHeading />); expect(screen.getByRole('heading', { level: 2, name: 'Welcome to the site' })).toBeInTheDocument(); });` and `it('renders the sub-heading in bold', () => { render(<WelcomeHeading />); expect(screen.getByRole('heading', { level: 2 })).toHaveStyle({ fontWeight: 'bold' }); });`
2. Run: `npx vitest run src/components/WelcomeHeading.test.jsx`. Expected: FAIL — the suite errors because `./WelcomeHeading` cannot be resolved (module not found).
3. Create `src/components/WelcomeHeading.jsx` exporting a default function component `WelcomeHeading()` that returns exactly `<h2 style={{ fontWeight: 'bold' }}>Welcome to the site</h2>`. Match the React/JSX import style used by sibling components (e.g. `src/components/ProductList.jsx`) — do not add any props, state, className, or CSS import.
4. Run: `npx vitest run src/components/WelcomeHeading.test.jsx`. Expected: PASS — 2 tests passed, 0 failed.
5. Commit: `git add src/components/WelcomeHeading.jsx src/components/WelcomeHeading.test.jsx && git commit -m "feat: add bold 'Welcome to the site' sub-heading component"`

**Verification:** `npx vitest run src/components/WelcomeHeading.test.jsx` exits 0 with both cases (`renders a level-2 heading with the exact text 'Welcome to the site'`, `renders the sub-heading in bold`) reporting passed.

### 2. Render the sub-heading at the top of the main page

**Objective:** Display `WelcomeHeading` on the application's main page by rendering it as the first child inside the ProductPage root element, and pin that placement with one new assertion in the existing ProductPage test file — with no other change to ProductPage or any other file.

**Files:** `src/components/ProductPage.test.jsx`, `src/components/ProductPage.jsx`

**Steps:**

1. Open `src/components/ProductPage.test.jsx` and note the existing render setup it uses (props, fetch/data mocks, wrappers). Add exactly one case to the existing top-level `describe`, reusing that same setup so the component renders successfully: `it("renders the 'Welcome to the site' sub-heading on the main page", () => { /* same render setup as the other cases in this file */ expect(screen.getByRole('heading', { level: 2, name: 'Welcome to the site' })).toBeInTheDocument(); });`
2. Run: `npx vitest run src/components/ProductPage.test.jsx`. Expected: FAIL — the new case fails with 'Unable to find role="heading"' while every pre-existing case still passes.
3. Modify `src/components/ProductPage.jsx`: add `import WelcomeHeading from './WelcomeHeading';` alongside the existing sibling imports, and render `<WelcomeHeading />` as the first child inside the component's existing outermost/root element, above the existing CategoryFilter/ProductList content. Make no other edit to this file (no prop changes, no markup changes, no className or CSS changes).
4. Run: `npx vitest run src/components/ProductPage.test.jsx`. Expected: PASS — the new case and all pre-existing ProductPage cases pass.
5. Run the full suite: `npx vitest run`. Expected: PASS — every pre-existing test file still passes, proving 'no other changes'.
6. Confirm the diff is limited to the intended files: `git status --porcelain` lists only `src/components/WelcomeHeading.jsx`, `src/components/WelcomeHeading.test.jsx`, `src/components/ProductPage.jsx`, `src/components/ProductPage.test.jsx`.
7. Commit: `git add src/components/ProductPage.jsx src/components/ProductPage.test.jsx && git commit -m "feat: show 'Welcome to the site' sub-heading on the main page"`

**Verification:** `npx vitest run src/components/ProductPage.test.jsx` and then `npx vitest run` both exit 0; `git status --porcelain` shows only the four intended files modified/added and no other tracked file changed.
