# Plan: Test for the Developer Agent

Story: #204
Issue: [#204](https://github.com/ricardoblackskye/webfeedpoc/issues/204)

## Goal

Add exactly one static footer line to the home route: 'Built by the Dark Factory - by the Developer Agent', rendered in italics. The change is confined to the home-route page component src/pages/HomePage.jsx (role="page", evidence: route "/" -> src/pages/HomePage.jsx) and deliberately not to the App shell (src/App.jsx, role="shell", evidence: renders an outlet, so it is rendered on every route), because the shell footer would leak the line onto /products/:slug, /category/:categoryName and /architecture. Italics come from a semantic <em> element, so no CSS file, no routing file, no config and no dependency changes are needed. A new co-located vitest/@testing-library test file proves the exact copy, the italic element, state-independence from product loading/empty states, and that the existing home page content is untouched.

## Approach

GOAL: the home page ('/' route) renders one additional line, 'Built by the Dark Factory - by the Developer Agent', in italics, and nothing else in the application changes.

PLACEMENT (the one real architectural decision): the evidence names two candidate owners. src/App.jsx has role="shell" with evidence 'renders an outlet, so it is rendered on every route'; it owns the existing <footer className="app-footer"> copyright line and is mounted for every path in the route table of src/entry-server.jsx and src/main.jsx. src/pages/HomePage.jsx has role="page" with evidence 'route "/" -> src/pages/HomePage.jsx'; it is the index-route element and composes CategoryFilter, SortControls, ProductList, Pagination and ProductModal, plus the 'All Items' heading. The story asks for a line on the home page and for no other changes, so the line goes into HomePage.jsx rather than into the App shell footer: the shell is shared by all routes, so putting it there would change every page. The line is appended to HomePage's existing fragment after the {selectedProduct && <ProductModal .../>} expression as <footer><p><em>Built by the Dark Factory - by the Developer Agent</em></p></footer>. <em> is italic by default in browsers and in the prerendered HTML, so no className and no CSS file are touched; a <footer> nested inside <main> is not a contentinfo landmark, so it does not duplicate the shell footer's landmark.

RENDER PATHS THAT MUST STAY CONSISTENT: HomePage is rendered client-side by src/main.jsx and at build time by scripts/prerender.mjs through render() in src/entry-server.jsx, so the new markup is static and data-independent. It must not sit inside any conditional that depends on products, loading, error, category or pagination state, otherwise the line would vanish for an empty catalogue or while loading.

TEST STRATEGY: a new co-located file src/pages/HomePage.test.jsx (vitest + @testing-library/react, matching the existing *.test.jsx convention used across src/components) renders HomePage directly. Because HomePage calls useSearchParams() and destructures products/loading/error/categories/productCounts/addToCart from useOutletContext(), the test wraps it in a MemoryRouter with a pathless layout route rendering <Outlet context={...} />. The copy is pinned once as a FOOTER_COPY constant so the hyphen (not an en dash), the capitalisation and the spacing are asserted verbatim; italics are asserted structurally (element tagName is EM) instead of through a CSS class jsdom would not load. Four tests: copy present; italics; line present while loading is true (guards against nesting it under the product-results conditional); existing home content still present next to the line (guards the 'no other changes' requirement).

TECH STACK: React 18 function components, react-router-dom v7, vitest, @testing-library/react. No new dependencies, no CSS, no config, no routing changes.

GLOBAL CONSTRAINTS (verbatim from the story): the line reads exactly 'Built by the Dark Factory - by the Developer Agent'; it is rendered in italics; it belongs to the home page; no other changes are permitted.

REVIEW FOCUS (conditions most likely to bite a user of this change, each pinned by a test in the task that owns the code):
1. Copy drift - an en dash instead of the hyphen, or 'Dark Factory'/'Developer Agent' recased - pinned by the exact-string assertion in 'renders the Dark Factory footer line on the home page'.
2. Italics delivered by a CSS class or an inline style that a later refactor drops - pinned by 'renders the footer line in italics using an em element', which asserts the rendered element is an <em>.
3. The line disappearing when the catalogue is empty or still loading - pinned by 'renders the footer line while products are still loading', which renders HomePage with loading: true and no products.
4. Scope leak: implementing the line in the shared App shell so it appears on product/category/architecture pages - pinned by the isolation of 'renders the Dark Factory footer line on the home page' (the assertion is satisfied by HomePage rendered on its own, with no shell) and confirmed by the reviewer diffing src/App.jsx as unchanged.
5. 'No other changes' regressions in the home page body - the category filter, heading, sort controls, product list, pagination and modal must still render - pinned by 'keeps the existing home page content alongside the footer line'.

EXECUTION ORDER: TDD - write the failing test file, watch it fail on the missing text, add the four-line markup to HomePage.jsx, watch it pass, run the whole unit suite and lint, then one focused commit.

## Tasks

### 1. Add the Dark Factory footer line to the home page (TDD)

**Objective:** Create a failing RTL test for the new home-page footer line, then add the exact italic line to src/pages/HomePage.jsx so all four tests pass, with no other file touched.

**Files:** `src/pages/HomePage.jsx`, `src/pages/HomePage.test.jsx`

**Steps:**

1. Create the new co-located test file `src/pages/HomePage.test.jsx` (vitest + @testing-library/react, matching the existing `*.test.jsx` convention in src/components). HomePage calls `useSearchParams()` and destructures `products, loading, error, categories, productCounts, addToCart` from `useOutletContext()`, so the tests supply those values through a pathless layout route that renders `<Outlet context={...} />`:

```jsx
import { describe, it, expect } from 'vitest'
import { render, screen } from '@testing-library/react'
import { MemoryRouter, Routes, Route, Outlet } from 'react-router-dom'
import HomePage from './HomePage'

const FOOTER_COPY = 'Built by the Dark Factory - by the Developer Agent'

function renderHomePage(overrides = {}) {
  const context = {
    products: [],
    loading: false,
    error: null,
    categories: [],
    productCounts: { All: 0 },
    addToCart: () => {},
    ...overrides,
  }

  return render(
    <MemoryRouter initialEntries={['/']}>
      <Routes>
        <Route element={<Outlet context={context} />}>
          <Route path="/" element={<HomePage />} />
        </Route>
      </Routes>
    </MemoryRouter>
  )
}

describe('HomePage footer line', () => {
  it('renders the Dark Factory footer line on the home page', () => {
    renderHomePage()
    expect(screen.getByText(FOOTER_COPY)).toBeDefined()
  })

  it('renders the footer line in italics using an em element', () => {
    renderHomePage()
    expect(screen.getByText(FOOTER_COPY).tagName).toBe('EM')
  })

  it('renders the footer line while products are still loading', () => {
    renderHomePage({ loading: true })
    expect(screen.getByText(FOOTER_COPY)).toBeDefined()
  })

  it('keeps the existing home page content alongside the footer line', () => {
    renderHomePage()
    expect(screen.getByRole('heading', { name: /All Items/ })).toBeDefined()
    expect(screen.getByText('No products available')).toBeDefined()
    expect(screen.getByText(FOOTER_COPY)).toBeDefined()
  })
})
```

Implementer note: `getByText` matches an element's own text nodes, so the query resolves to the `<em>` element rather than the `<p>` or `<footer>` wrapper - that is what makes the tagName assertion meaningful.
2. Run the new test file and confirm it fails for the right reason.

<em> is italic by default, so add no className and do not create or modify any CSS file; do not touch src/App.jsx, src/main.jsx, src/entry-server.jsx or any routing file.
