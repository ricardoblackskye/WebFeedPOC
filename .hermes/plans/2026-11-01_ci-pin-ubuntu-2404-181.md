# #181 — pin the CI runner to a supported Ubuntu

**Retrospective record.** The change was made before this file existed; it is written afterwards so
the repo's plan convention is not broken by a one-line CI fix. Treat it as a record, not a request.

## Why

`ubuntu-latest` rolled over to **Ubuntu 26.04**. Playwright 1.63 ships no Chromium build for it, so
the e2e job died on:

```
npx playwright install chromium
Failed to install browsers
Error: ERROR: Playwright does not support chromium on ubuntu26.04-x64
Error: Process completed with exit code 1.
```

No source changed. The runner image moved underneath a workflow that was green before, which is why
this surfaced on a branch (the Dark Factory's `feat/dark-factory-179`, PR #180) rather than on a
commit anyone would suspect.

## What changed

`.github/workflows/ci.yml`, both jobs:

```diff
-    runs-on: ubuntu-latest
+    runs-on: ubuntu-24.04
-    runs-on: ubuntu-latest
+    runs-on: ubuntu-24.04
```

**Two lines, not one.** The issue text asked for one, on the premise that the workflow had one job;
`ci.yml` has two — `test` (vitest) and `e2e` (`needs: test`, owning the Playwright step, and the job
that actually failed). Pinning only `e2e` would leave the same file half-exposed to the next
rollover, so both are pinned.

## Verification

- `grep -c "runs-on: ubuntu-latest" .github/workflows/ci.yml` → 0 after the change.
- The committed diff is 2 insertions / 2 deletions in one file — nothing else touched.
- Branch `fix/ci-pin-ubuntu-2404-181`, commit `b2e9e3d`, pushed and confirmed by `git ls-remote`.

## Deliberately out of scope

- `.github/workflows/mega-linter.yml` and `pr-reviewer.yml` still use `ubuntu-latest`. They do not
  install browsers, so this rollover does not break them the same way. Pinning them is a separate
  decision.
- Upgrading `@playwright/test` to a release that supports 26.04, and the alternative of using the
  official Playwright container. Both are valid; this issue chose the pin.
- `.hermes/plans/df-179.md` on the factory's branch is the Dark Factory's own file and uses its own
  `df-<issue>.md` naming, which differs from this repo's dated/slug convention. Not reconciled here.
