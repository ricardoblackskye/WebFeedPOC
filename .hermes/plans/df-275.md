# Plan: Test issue for Dark FActory issue 704

Story: #275
Issue: [#275](https://github.com/ricardoblackskye/webfeedpoc/issues/275)

## Goal

Add a single italic credit line, 'Built by the Dark Factory - by the Developer Agent', next to the existing copyright sentence in the site footer. The copyright text lives only in the shared application shell src/App.jsx (role: shell, renders an `<Outlet /> so it is mounted on every route, including the home route '/'), so the change is one JSX edit inside the existing <footer className="app-footer"> paragraph: the exact copy appended as an <em> element separated by a single space. <em>` is italicised by the user-agent stylesheet, so no CSS file is touched and no component, prop, route, or dependency is added. src/App.test.jsx ALREADY EXISTS in the repository and is therefore extended (not created) with five footer cases that pin the exact copy, the italics, the adjacency to the unchanged copyright sentence, the absence of any other footer change, and the presence of the copy in the synchronous (SSR/prerender-safe) markup.

## Approach

Where the change belongs. REPOSITORY EVIDENCE labels src/App.jsx role="shell" with the note 'renders an outlet, so it is rendered on every route'; src/main.jsx and src/entry-server.jsx both mount it at path "/" with src/pages/HomePage.jsx as the index child. That shell is the only file in the repository that composes a copyright line at the bottom of a page: `<footer className="app-footer"><p>&copy; {new Date().getFullYear()} {SITE_NAME}. All rights reserved.</p></footer>`. The story's instruction — 'put this next to the copyright text at the bottom of the page' — therefore resolves to that paragraph. No page-level file changes: putting a second copyright/credit block inside src/pages/HomePage.jsx would duplicate the footer the story told us not to disturb.

What the edit is. Inside the existing `<p>, after the copyright sentence, append a single space and <em>Built by the Dark Factory - by the Developer Agent</em>. The copy is verbatim from the story body: ASCII hyphen-minus (not an em dash or en dash), 'Factory' (the story title's 'FActory' is a typo in the title, not in the copy), no smart quotes, no trailing period. <em>` is italic by default in the UA stylesheet, which is how 'in italics' is satisfied without touching App.css, adding a class, or introducing an inline style — honouring 'No other changes.' The existing sentence (entity &copy;, the dynamic year, SITE_NAME, 'All rights reserved.') is left byte-identical and stays first in the paragraph, so the new text renders 'next to' it on the same line and wraps normally on narrow viewports.

Blast radius. Because the footer is in the shell, the credit line also renders on the other routes the shell wraps (/products/:slug, /category/:categoryName, /architecture) and in the prerendered HTML written by scripts/prerender.mjs, which renders the same App component through src/entry-server.jsx. That is inherent to placing the text next to the only copyright block in the app; there is no home-page-only footer to target, and introducing one would be a larger change than the story allows. No route table, no Helmet metadata, no cart markup is touched.

How it is proven. src/App.test.jsx already exists, so it is EXTENDED with a new describe block rather than replaced: keep every existing case and its imports intact, add any missing imports (HelmetProvider, QueryClient/QueryClientProvider, MemoryRouter, useWixProducts/useWixCart/wixCheckoutService mocks) only if they are not already present, and append the five footer assertions. The App is rendered inside HelmetProvider + MemoryRouter + QueryClientProvider — the same provider stack src/main.jsx wires — with useWixProducts, useWixCart and wixCheckoutService mocked, so the shell renders deterministically without network calls.

Review focus — inputs and conditions the story implies but does not spell out, most likely first. (a) Copy fidelity: the title spells 'FActory' while the body spells 'Factory', and the separator is a hyphen — a well-meaning editor could 'fix' either; the exact-string assertion pins it. (b) Italics actually rendering: an implementation using a plain `<span> without CSS looks upright, so the tagName assertion pins the semantic element. (c) Adjacency: if the credit is emitted as a new sibling <p>` it is no longer 'next to the copyright text'; the single-paragraph assertion pins it. (d) Prerendered/SSR output: the production home page is statically generated by scripts/prerender.mjs from the same shell, so the line must exist in the initial render, not behind an effect; the synchronous-markup assertion pins it. (e) Narrow viewports (360px profiles in playwright.config.cjs): the longer footer line must wrap rather than overflow, which it does because the text is inline inside the existing wrapping paragraph and no white-space rule is introduced — verified by not adding any nowrap/inline style.

2. Step 2 — Extend src/App.test.jsx by appending one new describe block at the end of the file (and adding only the imports that are not already present). The block to append:

describe('App footer', () => {
  const CREDIT_TEXT = 'Built by the Dark Factory - by the Developer Agent'

  function renderApp() {
    const queryClient = new QueryClient({ defaultOptions: { queries: { retry: false } } })
    return render(
      `<QueryClientProvider client={queryClient}>`
        `<HelmetProvider>`
          `<MemoryRouter initialEntries={['/']}>`
            `<App />`
          `</MemoryRouter>`
        `</HelmetProvider>`
      `</QueryClientProvider>`
    )
  }

  it('renders the exact credit copy in the footer', () => {
    renderApp()
    const credit = screen.getByText(CREDIT_TEXT)
    expect(credit).toBeDefined()
    expect(credit.closest('footer.app-footer')).not.toBeNull()
  })

  it('renders the credit copy in italics', () => {
    renderApp()
    expect(screen.getByText(CREDIT_TEXT).tagName).toBe('EM')
  })

  it('renders the credit next to the existing copyright sentence', () => {
    renderApp()
    const credit = screen.getByText(CREDIT_TEXT)
    const paragraph = credit.closest('p')
    expect(paragraph).not.toBeNull()
    expect(paragraph.textContent).toContain('All rights reserved.')
    expect(paragraph.textContent).toContain(String(new Date().getFullYear()))
    expect(paragraph.textContent.trim().endsWith(CREDIT_TEXT)).toBe(true)
  })

  it('adds nothing else to the footer', () => {
    renderApp()
    const footer = document.querySelector('footer.app-footer')
    expect(footer).not.toBeNull()
    expect(footer.querySelectorAll('p')).toHaveLength(1)
    expect(footer.querySelectorAll('em')).toHaveLength(1)
    expect(footer.querySelector('em').textContent).toBe(CREDIT_TEXT)
  })

  it('renders the credit in the synchronous initial markup (SSR/prerender safe)', () => {
    const { container } = renderApp()
    expect(container.innerHTML).toContain(CREDIT_TEXT)
  })
})

Required imports for this block, added only if absent from the file's existing import list: `import { describe, it, expect, vi } from 'vitest'`, `import { render, screen } from '@testing-library/react'`, `import { MemoryRouter } from 'react-router-dom'`, `import { HelmetProvider } from 'react-helmet-async'`, `import { QueryClient, QueryClientProvider } from '@tanstack/react-query'`, `import App from './App'`. The mock specifiers are relative to src/App.test.jsx, matching how src/App.jsx imports './hooks/useWixProducts' and './hooks/useWixCart' and how src/components/Cart.jsx imports './services/wixCheckoutService':
