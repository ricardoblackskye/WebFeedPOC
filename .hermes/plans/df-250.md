# Plan: Test for the Dark Factory - running concurrently

Story: #250
Issue: [#250](https://github.com/ricardoblackskye/webfeedpoc/issues/250)

## Goal

One-file UI change on the home route: src/pages/HomePage.jsx — the page component that src/entry-server.jsx mounts as the index route of the '/' App route — gains a trailing `<footer> whose only content is an italic <em> line reading exactly 'Built by the Dark Factory - by the Developer Agent - concurrent'. No stylesheet, router, SSR or prerender changes are needed, because <em>` supplies the italics natively and scripts/prerender.mjs renders '/' through src/entry-server.jsx -> src/App.jsx -> src/pages/HomePage.jsx. A new co-located Vitest/React Testing Library spec, src/pages/HomePage.test.jsx, mounts the page through a stubbed `<Outlet context>` and proves the exact copy, the italic markup and a single render in the loading state.

## Approach

Placement: the app-wide footer lives in src/App.jsx (`<footer className="app-footer">), and App renders the <Outlet>, so that footer is emitted on every route (/, /products/:slug, /category/:categoryName, /architecture, /about, /orders, /order-confirmation). The story asks for the line on the home page only, so the line must not go into App.jsx. src/pages/HomePage.jsx is the component the route evidence names for '/', and it already owns everything else that is home-page-only (CategoryFilter, SortControls, ProductList, Pagination, ProductModal). The new footer is appended as the last child of the fragment that HomePage returns, immediately after the {selectedProduct && (<ProductModal ... />)} block, so it renders in every home-page state (loading, error, empty, filtered) and in no other route. Markup and styling: the line is wrapped as <footer className="home-footer"><p><em>Built by the Dark Factory - by the Developer Agent - concurrent</em></p></footer>. The <em> element renders italic by default, which satisfies 'in italics' without adding a stylesheet; HomePage has no sibling CSS file in this repository (each component owns its own, e.g. src/components/Cart.css next to src/components/Cart.jsx), and the story says 'No other changes', so no HomePage.css is created and no existing CSS is edited. The copy is inserted verbatim: ASCII hyphens surrounded by single spaces, no trailing period, exact capitalisation. Pipeline impact: scripts/prerender.mjs builds an SSR bundle from src/entry-server.jsx and renders '/' with { products }, and src/entry-server.jsx maps the index route of the '/' App route to HomePage, so the prerendered dist/index.html inherits the footer automatically; no change to src/entry-server.jsx, src/main.jsx, the prerender script or the sitemap is required. Testing: no existing spec mounts the home page — the co-located specs under src/components/* test their own components in isolation (for example src/components/ProductList.test.jsx) — so a new co-located spec src/pages/HomePage.test.jsx mounts HomePage with MemoryRouter/Routes and a small HomeOutlet stub that supplies the useOutletContext values HomePage consumes (products, loading, error, categories, productCounts, addToCart), wrapped in HelmetProvider. With products: [], itemListSchema is null so the Helmet block is not rendered and ProductList/Pagination/ProductModal never mount, which keeps the assertion narrow: getByText for the exact copy, then the same node's tagName === 'EM', then getAllByText length 1 while loading is true. Risks reviewed before code exists: (1) Copy fidelity — wrong case, an en dash instead of a hyphen, or a trailing period would pass a loose check but fail the story; the test asserts the exact string. (2) Italics — if the line were emitted as a plain <p> it would look correct in a diff but not be italic; the test pins the <em> element. (3) Scope — the tempting App.jsx footer would change every route and any backend-conditional footer would render twice; the diff-scope check in Task 2 confirms only the page and its spec changed. (4) Duplicate or inconsistent rendering across home-page states — the loading-state test pins a single instance. (5) Semantic role side effect — the footer sits inside App's <main>`, so it does not receive the contentinfo role; the test asserts on the text and tag, not on a landmark role, so no a11y role regresses.

## Tasks

### 1. Add the Dark Factory credit line to the home page and prove it with a co-located test

**Objective:** Render the italic footer line with the exact story copy at the end of src/pages/HomePage.jsx, driven by a failing-then-passing Vitest/React Testing Library spec at src/pages/HomePage.test.jsx.

**Files:** `src/pages/HomePage.test.jsx`, `src/pages/HomePage.jsx`

**Steps:**

1. Write the failing test file `src/pages/HomePage.test.jsx` (new, co-located with the page it covers):

```jsx
import { describe, it, expect, vi } from 'vitest'
import { render, screen } from '@testing-library/react'
import { MemoryRouter, Routes, Route, Outlet } from 'react-router-dom'
import { HelmetProvider } from 'react-helmet-async'
import HomePage from './HomePage'

const CREDIT_LINE = 'Built by the Dark Factory - by the Developer Agent - concurrent'

function HomeOutlet({ products = [], loading = false }) {
  return (
    <Outlet
      context={{
        products,
        loading,
        error: null,
        categories: [],
        productCounts: { All: products.length },
        addToCart: vi.fn(),
      }}
    />
  )
}

function renderHomePage(props = {}) {
  return render(
    <HelmetProvider>
      <MemoryRouter initialEntries={['/']}>
        <Routes>
          <Route path="/" element={<HomeOutlet {...props} />}>
            <Route index element={<HomePage />} />
          </Route>
        </Routes>
      </MemoryRouter>
    </HelmetProvider>,
  )
}

describe('HomePage Dark Factory credit line', () => {
  it('renders the credit line with the exact copy from the story', () => {
    renderHomePage()
    expect(screen.getByText(CREDIT_LINE)).toBeDefined()
  })

  it('renders the credit line in italics via an em element', () => {
    renderHomePage()
    expect(screen.getByText(CREDIT_LINE).tagName).toBe('EM')
  })

  it('renders the credit line exactly once while products are loading', () => {
    renderHomePage({ loading: true })
    expect(screen.getAllByText(CREDIT_LINE)).toHaveLength(1)
  })
})
```
2. Run `npx vitest run src/pages/HomePage.test.jsx`. Expected: FAIL — the first two cases fail with 'Unable to find an element with the text: Built by the Dark Factory - by the Developer Agent - concurrent'; the third fails on a zero-length match list.
3. Implement in `src/pages/HomePage.jsx`: add the footer as the last child of the fragment `HomePage` returns, immediately after the `{selectedProduct && (<ProductModal product={selectedProduct} onClose={handleCloseModal} onAddToCart={addToCart} />)}` block and before the closing `</>`:

```jsx
      <footer className="home-footer">
        <p>
          <em>Built by the Dark Factory - by the Developer Agent - concurrent</em>
        </p>
      </footer>
```

The literal string is inserted verbatim: capital B, capital D and capital F, ASCII hyphens with a single space either side, no trailing period. `<em>` is used because it is italic by default, so no CSS file is added and no existing CSS is edited.
4. Run `npx vitest run src/pages/HomePage.test.jsx`. Expected: PASS — 3 passed.
5. Run `npx vitest run`. Expected: PASS — the new spec plus every pre-existing suite (Cart, CategoryFilter, ImageModal, Pagination, ProductCard, ProductList, ProductModal, ProductPage, SortControls, StockIndicator) green, 0 failures.
6. Commit:

```bash
git add src/pages/HomePage.jsx src/pages/HomePage.test.jsx
git commit -m "feat: add Dark Factory credit line to home page footer"
```

**Verification:** `npx vitest run src/pages/HomePage.test.jsx` reports 3/3 passing, and `npx vitest run` reports the full suite green with no new failures. Inspecting the rendered output of the first test shows a single `<em>` node whose text content is exactly 'Built by the Dark Factory - by the Developer Agent - concurrent'.
