# Plan: Test for DF issue 659

Story: #212
Issue: [#212](https://github.com/ricardoblackskye/webfeedpoc/issues/212)

## Goal

Adds one static, italic credit line to the home page route only. src/pages/HomePage.jsx — the component that src/entry-server.jsx and src/main.jsx both mount at the index route under '/', and which composes the home page's CategoryFilter, SortControls, ProductList, Pagination and ProductModal inside the App.jsx shell — gains a single <p className="home-credit"> element as the last child of its returned fragment, carrying the exact copy 'Built by the Dark Factory - by the Developer Agent' and an inline fontStyle of italic. Because the italic is applied inline, no stylesheet, no new component, and no dependency is touched anywhere else in the repository, and because HomePage is the only component that renders on '/', the string appears on no other route (the site-wide <footer className="app-footer"> already rendered by src/App.jsx on every route is deliberately left unchanged). A new unit test, src/pages/HomePage.test.jsx, pins the exact copy and the italic style.

## Approach

Scope decision first: the story says 'add a footer line to the home page ... No other changes'. The evidence names exactly one UI entry point for that surface — src/entry-server.jsx declares the route table with `<Route index element={<HomePage />} />` inside the `/` route owned by App.jsx, and src/main.jsx mounts the same HomePage at the index route — so the change belongs in src/pages/HomePage.jsx, not in the App.jsx app shell. Adding the line to App.jsx's existing `<footer className="app-footer">` was rejected: that footer renders on every route (product, category, architecture, orders, release notes), so the string would leak onto pages the story did not ask for. HomePage.jsx is the correct, narrowly-scoped home page entry point and is already responsible for the page's visible content.

Implementation: append a single paragraph as the last child of HomePage's returned fragment, after the `{selectedProduct && (<ProductModal ... />)}` block:

```jsx
<p className="home-credit">
  Built by the Dark Factory - by the Developer Agent
</p>
```

The copy is transcribed verbatim from the story: capital B on 'Built', capital D and F on 'Dark Factory', capital D and A on 'Developer Agent', a plain ASCII hyphen-minus surrounded by single spaces between the two clauses, no trailing period. Nothing else in the component's JSX is reordered, renamed, or removed.

Italics: the page is styled exclusively by global stylesheets (src/index.css, src/App.css) that HomePage.jsx does not import; it has no page-local stylesheet. To honour 'no other changes' the italic is applied as an inline `style={{ fontStyle: 'italic' }}` on the credit paragraph rather than by editing a global stylesheet or creating a new CSS file. Inline style is also deterministic under jsdom, so the test can assert the rendered style directly instead of relying on a user-agent stylesheet that jsdom does not apply (which is why a bare `<em>` was rejected as the sole mechanism). The element is a `<p>`, not a second `<footer>`: a `<footer>` nested inside the `<main>` landmark of App.jsx is scoped and would add a second, ambiguous footer landmark to the accessibility tree, while the story only asks for a footer *line*.

Testing: src/pages/HomePage.jsx reads `useOutletContext()` (for products, categories, productCounts, addToCart) and `useSearchParams()` (for the search term), so the unit test must mount it inside a MemoryRouter with a parent route that supplies the outlet context — `<Route path="/" element={<Outlet context={outletContext} />}>` with an index child route rendering HomePage. The default context is `{ products: [], loading: false, error: null, categories: [], productCounts: { All: 0 }, addToCart: vi.fn() }`, which makes the render deterministic: with an empty product list the page renders its existing 'No products available' branch, the Helmet/itemListSchema branch is skipped (products.length === 0), and no Wix or Stripe service is contacted. Three assertions cover the requirement: the credit text is present with the exact copy; it renders exactly once while pre-existing home page content ('No products available') is still present; and the element's `style.fontStyle` is 'italic'.

Downstream effects: HomePage is the component prerendered to dist/index.html for '/' by scripts/prerender.mjs, so the line will be present in the static HTML as well as after hydration. That is the desired outcome and requires no change to scripts/prerender.mjs, the route table in src/entry-server.jsx, or src/main.jsx. No npm dependency is added, no API route is touched, and no other route's prerendered output changes because no other route renders HomePage.

## Tasks

### 1. Render the exact Dark Factory credit line on the home page

**Objective:** Pin the verbatim credit copy on the home page route with a failing-then-passing unit test, and add the paragraph to src/pages/HomePage.jsx without disturbing any existing home page markup.

**Files:** `src/pages/HomePage.jsx`, `src/pages/HomePage.test.jsx`

**Steps:**

1. Create the test file `src/pages/HomePage.test.jsx` (new file — the home page has no test in the repository listing) with a `renderHomePage(context = {})` helper that supplies the outlet context HomePage reads via `useOutletContext()` and the router that `useSearchParams()` needs:
```jsx
import { describe, it, expect, vi } from 'vitest'
import { render, screen } from '@testing-library/react'
import { MemoryRouter, Routes, Route, Outlet } from 'react-router-dom'
import HomePage from './HomePage'

const CREDIT_TEXT = 'Built by the Dark Factory - by the Developer Agent'

function renderHomePage(context = {}) {
  const outletContext = {
    products: [],
    loading: false,
    error: null,
    categories: [],
    productCounts: { All: 0 },
    addToCart: vi.fn(),
    ...context,
  }

  return render(
    <MemoryRouter initialEntries={['/']}>
      <Routes>
        <Route path="/" element={<Outlet context={outletContext} />}>
          <Route index element={<HomePage />} />
        </Route>
      </Routes>
    </MemoryRouter>
  )
}
```
2. Add the failing test `renders the Dark Factory credit line with the exact copy` (inside `describe('HomePage - Dark Factory credit', ...)`) asserting the verbatim string is rendered: `renderHomePage()` then `expect(screen.getByText('Built by the Dark Factory - by the Developer Agent')).toBeDefined()`. Use the raw string, not the CREDIT_TEXT constant, so a typo in the constant cannot mask a typo in the component.
3. Add the failing test `renders the credit line without removing existing home page content` asserting `expect(screen.getByText('No products available')).toBeDefined()` and `expect(screen.getAllByText(CREDIT_TEXT)).toHaveLength(1)`.
4. Run: `npm test -- --run src/pages/HomePage.test.jsx` — expect both tests to FAIL with 'Unable to find an element with the text: Built by the Dark Factory - by the Developer Agent' (the 'No products available' assertion inside the second test passes; the whole test still fails).
5. Implement in `src/pages/HomePage.jsx`: add, as the last child of the returned fragment — immediately after the `{selectedProduct && (<ProductModal product={selectedProduct} onClose={handleCloseModal} onAddToCart={addToCart} />)}` block and before the closing `</>` — this element, copying the text verbatim (capital B, capital D/F, capital D/A, plain ASCII hyphen-minus with one space either side, no trailing punctuation):
```jsx
<p className="home-credit">
  Built by the Dark Factory - by the Developer Agent
</p>
```
Do not touch any other line of the component.
6. Run: `npm test -- --run src/pages/HomePage.test.jsx` — expect PASS for both tests.
7. Run: `npm run lint` — expect no new errors.
8. Commit:
```bash
git add src/pages/HomePage.jsx src/pages/HomePage.test.jsx
git commit -m "feat(home): add Dark Factory credit line to home page"
```

**Verification:** `npm test -- --run src/pages/HomePage.test.jsx` passes both credit-line tests, and `npm run lint` reports no new errors. The two new test names appear in the vitest output as passing.

### 2. Render the credit line in italics

**Objective:** Make the credit paragraph italic via an inline style so the home page's global stylesheets and every other component in the repository remain untouched, and prove it with a style assertion.

**Files:** `src/pages/HomePage.jsx`, `src/pages/HomePage.test.jsx`

**Steps:**

1. Add the failing test `renders the credit line in italics` (inside `describe('HomePage - credit line styling', ...)`) to `src/pages/HomePage.test.jsx`: `renderHomePage()`, then `const credit = screen.getByText(CREDIT_TEXT)`, then `expect(credit.style.fontStyle).toBe('italic')`. Assert the rendered inline style rather than a computed style, because jsdom does not apply user-agent or stylesheet rules, so a bare `<em>` would not be observable here.
2. Run: `npm test -- --run src/pages/HomePage.test.jsx` — expect the new test to FAIL with the empty string from `credit.style.fontStyle` (the two credit-line tests from Task 1 keep passing).
3. Implement in `src/pages/HomePage.jsx`: add the inline style to the existing credit paragraph so it reads
```jsx
<p className="home-credit" style={{ fontStyle: 'italic' }}>
  Built by the Dark Factory - by the Developer Agent
</p>
```
Do not edit src/index.css, src/App.css, or any other stylesheet — an inline style is what keeps this change confined to the home page.
4. Run: `npm test -- --run src/pages/HomePage.test.jsx` — expect all three tests to PASS.
5. Run: `npm test -- --run` — expect the whole unit suite to PASS, proving no other component or page test regressed.
6. Run: `npm run lint` — expect no new errors.
7. Commit:
```bash
git add src/pages/HomePage.jsx src/pages/HomePage.test.jsx
git commit -m "style(home): render Dark Factory credit line in italics"
```

**Verification:** `npm test -- --run src/pages/HomePage.test.jsx` passes all three tests including `renders the credit line in italics`, and the full `npm test -- --run` suite plus `npm run lint` are green with no pre-existing test modified.
