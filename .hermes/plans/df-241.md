# Plan: Test Issue for Dark Factory issue #698

Story: #241
Issue: [#241](https://github.com/ricardoblackskye/webfeedpoc/issues/241)

## Goal

One additive UI change on the home route only: src/pages/HomePage.jsx (the component src/entry-server.jsx maps to the index route of '/') gains a final italic credit line rendered by an `<em> element containing the exact story copy. No new components, styles, routes, or data flow are introduced — the italics come from the <em>` element itself, so no CSS file is created and no other page or shell is touched. A new co-located Vitest test, src/pages/HomePage.test.jsx, mounts the page through a MemoryRouter route whose parent element supplies the outlet context HomePage reads via useOutletContext, and pins the exact copy, the italic rendering, the single occurrence, and the fact that the credit survives the loading state.

## Approach

HomePage.jsx currently returns a React fragment that composes CategoryFilter, the 'All Items' heading, SortControls, ProductList + Pagination, the loading/error/empty states and ProductModal. The change is to append one more element to the end of that fragment, immediately after the {selectedProduct && (`<ProductModal ... />`)} block and before the closing </>: a `<p className="home-footer-credit"> whose only child is an <em>` element whose text node is exactly `Built by the Dark Factory - by the Developer Agent`. The copy is kept on a single line inside the `<em> so JSX emits one text node with no leading or trailing whitespace, and it uses a plain ASCII hyphen-minus with single spaces on either side, matching the story body verbatim (the &apos; entities in the story are quotation marks around the phrase, not part of the copy). Using <em> rather than a CSS class on the <p>` means the italics come from the element's built-in italic rendering: no new stylesheet, no change to App.jsx's existing .app-footer, and no effect on the product, category, architecture, order or release-notes routes, which is what 'no other changes' requires. Because HomePage is also rendered server-side by src/entry-server.jsx for the index route of '/', the credit will appear in the prerendered dist/index.html without any additional work. Verification is by a new Vitest file, src/pages/HomePage.test.jsx, which is the sibling test of the page component in the same way src/components/Cart.test.jsx is the sibling test of src/components/Cart.jsx. It renders HomePage inside HelmetProvider and a MemoryRouter, using a parent <Route path="/" element={`<Outlet context={outletContext} />`}> with an index child so that useOutletContext resolves against a stub context (products, loading, error, categories, productCounts, addToCart) and useSearchParams resolves against the router. Four assertions cover the risk surface: exact copy, EM element (italics), a single occurrence plus the pre-existing 'All Items' heading still present (no collateral change), and the credit still rendering while loading is true (the credit belongs to the page, not to the product list). The plan is written test-first: create the failing test, watch it fail with 'Unable to find an element with the text', add the three-line JSX block, watch it pass, run the full suite and lint, then a prerender grep as an SSR smoke check.

## Tasks

### 1. Add the italic Dark Factory credit line to the home page footer

**Objective:** src/pages/HomePage.jsx renders, as the final child of its returned fragment, a line reading exactly 'Built by the Dark Factory - by the Developer Agent' inside an `<em>` element, proven by a new co-located Vitest test, with the rest of the home page and every other route unchanged.

**Files:** `src/pages/HomePage.jsx`, `src/pages/HomePage.test.jsx`

**Steps:**

1. Create `src/pages/HomePage.test.jsx` with exactly this content (it renders the page through a route that supplies the outlet context HomePage reads via useOutletContext, and wraps it in HelmetProvider because HomePage renders `<Helmet>`):

```jsx
import { describe, it, expect, vi } from 'vitest'
import { render, screen } from '@testing-library/react'
import { MemoryRouter, Routes, Route, Outlet } from 'react-router-dom'
import { HelmetProvider } from 'react-helmet-async'
import HomePage from './HomePage'

const CREDIT = 'Built by the Dark Factory - by the Developer Agent'

function renderHomePage(overrides = {}) {
  const outletContext = {
    products: [],
    loading: false,
    error: null,
    categories: [],
    productCounts: { All: 0 },
    addToCart: vi.fn(),
    ...overrides,
  }

  return render(
    <HelmetProvider>
      <MemoryRouter initialEntries={['/']}>
        <Routes>
          <Route path="/" element={<Outlet context={outletContext} />}>
            <Route index element={<HomePage />} />
          </Route>
        </Routes>
      </MemoryRouter>
    </HelmetProvider>
  )
}

describe('HomePage footer credit', () => {
  it('renders the Dark Factory footer credit with the exact story copy', () => {
    renderHomePage()
    expect(screen.getByText(CREDIT)).toBeDefined()
  })

  it('renders the footer credit in italics', () => {
    renderHomePage()
    expect(screen.getByText(CREDIT).tagName).toBe('EM')
  })

  it('renders the footer credit once and leaves the existing home page content unchanged', () => {
    renderHomePage()
    expect(screen.getAllByText(CREDIT)).toHaveLength(1)
    expect(screen.getByRole('heading', { name: /All Items/ })).toBeDefined()
  })

  it('renders the footer credit while products are still loading', () => {
    renderHomePage({ loading: true })
    expect(screen.getByText(CREDIT)).toBeDefined()
  })
})
```

Note: `getByText` matches the element whose own text nodes equal the string, which is why the credit must be the only text inside the `<em>`; the heading is asserted by accessible role because its text also contains the product count span.
2. Run: `npx vitest run src/pages/HomePage.test.jsx`
Expected: FAIL on all four cases with `TestingLibraryElementError: Unable to find an element with the text: Built by the Dark Factory - by the Developer Agent` (the file compiles and the harness mounts, so the failure is the missing copy, not a setup error).
3. In `src/pages/HomePage.jsx`, add this as the LAST child of the fragment returned by HomePage — immediately after the `{selectedProduct && (<ProductModal ... />)}` block and before the closing `</>`:

```jsx
      <p className="home-footer-credit">

```

Keep the copy on one line inside the `<em> so JSX emits a single text node with no surrounding whitespace, use an ASCII hyphen-minus with one space either side, and add no CSS file or class definition — the italics come from the <em>` element itself. Change nothing else in the file.
4. Run: `npx vitest run src/pages/HomePage.test.jsx`
Expected: PASS — 4 passed (4).
5. Run the full unit suite: `npx vitest run`
Expected: PASS — the existing src/components/*.test.jsx suites (Cart, CategoryFilter, ImageModal, Pagination, ProductCard, ProductList, ProductModal, ProductPage, SortControls, StockIndicator) are unaffected.
6. SSR/prerender smoke check: run `npm run build:prerender` then `grep -c "Built by the Dark Factory" dist/index.html`
Expected: `1` — src/entry-server.jsx renders the same HomePage component for the index route of '/'. If the Wix fetch fails the script still prerenders with an empty product list, and the count must still be 1.
7. Run: `npm run lint`
Expected: PASS with no new errors.

