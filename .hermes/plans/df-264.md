# Plan: Test issue for Dark Factory (759) x2

Story: #264
Issue: [#264](https://github.com/ricardoblackskye/webfeedpoc/issues/264)

## Goal

Add one static, italic line of copy — 'Built by the Dark Factory - by the Developer Agent' — to the home page only. The change is confined to src/pages/HomePage.jsx, the page component that both the client router (src/main.jsx, route index under '/') and the SSR prerender path (src/entry-server.jsx, '<Route index element={`<HomePage />`} />') render for the '/' route. The line is emitted as an `<em>` (italic by default) inside a single footer element appended as the last child of HomePage's returned fragment, so no stylesheet, no shared component, and no global shell (src/App.jsx, whose '.app-footer' renders on every route) is touched. A new unit test file proves the copy, the italics, the route scope, and SSR parity; a final verification task proves the full suite, lint, and the prerendered dist/index.html.

## Approach

Goal: the home page renders exactly one extra italic line reading 'Built by the Dark Factory - by the Developer Agent', and nothing else in the repository changes.

Architecture: The repository's route table lives in two places that must stay consistent — src/main.jsx (BrowserRouter) and src/entry-server.jsx (StaticRouter used by scripts/prerender.mjs). Both mount App as the shell for '/' and render HomePage.jsx as the index route. HomePage.jsx is therefore the correct and only insertion point: putting the line in App.jsx would place it on /products/:slug, /category/:categoryName, /architecture and every other route, which the story forbids ('No other changes'), and putting it in any src/components/* file would leak it into ProductList, CategoryFilter, Pagination or the cart drawer that those components also compose. HomePage has no companion stylesheet in the repository evidence (no src/pages/*.css is referenced by it — it imports only components and utils/structuredData), so italics are expressed semantically with the `<em>` element rather than a new CSS rule; this keeps the change to one JSX node and keeps the markup identical between client render and prerender (no hydration mismatch, no new CSS file to load).

Tech Stack: React 18 JSX (no TypeScript in this file), react-router-dom v7 (Routes/Route/Outlet/useSearchParams) with StaticRouter imported from 'react-router' for the SSR variant, react-helmet-async, Vitest + @testing-library/react + jsdom, ESLint, and the existing Vite prerender script (npm run build:prerender).

Global Constraints (apply to every task):
- Copy is exactly: Built by the Dark Factory - by the Developer Agent — capitalised 'Dark Factory' and 'Developer Agent', a U+002D hyphen-minus with one space either side (not an en/em dash), no trailing period, no surrounding quotation marks.
- The line is rendered in italics and is the only new DOM node; no other line, attribute, import, export, prop or file may change.
- The node must be static (no Date, no window, no random values) because HomePage is server-rendered for '/' by scripts/prerender.mjs.
- Scope is the home page only; src/App.jsx's global '.app-footer', all src/components/* files, and every other route remain byte-identical.
- No new npm dependency.

Review Focus (inputs/conditions the story implies but no acceptance criterion states outright; each has a test in the task that owns the code):
1. Copy exactness — a user reading the home page must see the exact sentence; a curly apostrophe, an en dash instead of the hyphen-minus, or a trailing period would silently ship. Pinned by the exact-string assertions in HomePage.test.jsx.
2. Real italics — the line must actually be italic, not merely carry a class name that no stylesheet defines (there is no HomePage stylesheet). Pinned by asserting the element tagName is 'EM'.
3. Route scope and non-duplication — the line must appear exactly once and must not be pulled in from the global App shell (which would show it on every route). Pinned by the 'exactly once' + existing-content-intact assertions.
4. Server-render parity — HomePage is rendered through StaticRouter during npm run build:prerender, so the node must render identically there. Pinned by the StaticRouter test case.
5. Prerender artefact — the shipped dist/index.html (not just the jsdom tree) must contain the line and non-home prerendered pages must not. Pinned by Task 2's HTML checks.

Execution: Task 1 is a strict TDD cycle (failing test → minimal JSX → green → commit). Task 2 is an independent verification gate a reviewer can reject on its own (full suite, lint, prerendered HTML scope check) without reopening Task 1's design.

## Tasks

### 1. Add the italic Dark Factory footer line to the home page (TDD)

**Objective:** Render exactly one italic line 'Built by the Dark Factory - by the Developer Agent' at the end of HomePage's output, proven by a new unit test file that also pins italics, single-render scope and SSR parity.

**Files:** `src/pages/HomePage.jsx`, `src/pages/HomePage.test.jsx`

**Steps:**

1. Create `src/pages/HomePage.test.jsx` with exactly this content:

```jsx
import { describe, it, expect, vi } from 'vitest'
import { render, screen } from '@testing-library/react'
import { MemoryRouter, Routes, Route, Outlet } from 'react-router-dom'
import { StaticRouter } from 'react-router'
import { HelmetProvider } from 'react-helmet-async'
import HomePage from './HomePage'

const FOOTER_LINE = 'Built by the Dark Factory - by the Developer Agent'

// HomePage reads everything through useOutletContext() and useSearchParams(),
// so it must be mounted inside a router that supplies both a route context and
// a location. The context shape mirrors App.jsx's <Outlet context={{...}} />.
const outletContext = {
  products: [],
  loading: false,
  error: null,
  categories: [],
  productCounts: { All: 0 },
  addToCart: vi.fn(),
}

const routes = (
  <Routes>
    <Route path="/" element={<Outlet context={outletContext} />}>
      <Route index element={<HomePage />} />
    </Route>
  </Routes>
)

function renderHomePage() {
  return render(
    <HelmetProvider>
      <MemoryRouter initialEntries={['/']}>{routes}</MemoryRouter>
    </HelmetProvider>
  )
}

describe('HomePage Dark Factory footer line', () => {
  it('renders the Dark Factory footer line on the home page', () => {
    renderHomePage()
    expect(screen.getByText(FOOTER_LINE)).toBeDefined()
  })

  it('renders the Dark Factory footer line as italic text (em element)', () => {
    renderHomePage()
    expect(screen.getByText(FOOTER_LINE).tagName).toBe('EM')
  })

  it('renders the footer line exactly once without changing existing home page content', () => {
    const { container } = renderHomePage()
    expect(screen.getAllByText(FOOTER_LINE)).toHaveLength(1)
    expect(screen.getByRole('heading', { name: /All Items/ })).toBeDefined()
    expect(container.textContent).not.toContain('All rights reserved')
  })

  it('renders the footer line under the SSR router used by prerendering', () => {
    render(
      <HelmetProvider>
        <StaticRouter location="/">{routes}</StaticRouter>
      </HelmetProvider>
    )
    expect(screen.getByText(FOOTER_LINE).tagName).toBe('EM')
  })
})
```
2. Run the new test file and confirm it fails for the right reason.

Run: `npx vitest run src/pages/HomePage.test.jsx`
Expected: FAIL — 'Unable to find an element with the text: Built by the Dark Factory - by the Developer Agent' in all four cases; the file compiles and the router/Helmet harness itself produces no errors.
3. Append the footer line to `src/pages/HomePage.jsx` as the last child of the returned fragment — immediately after the `{selectedProduct && (<ProductModal ... />)}` block and before the closing `</>`:

```jsx
      <footer className="home-footer-line">
        <em>Built by the Dark Factory - by the Developer Agent</em>
      </footer>
```

Use the literal string with a hyphen-minus and single spaces around it. Do not add an import, a prop, a style rule, or any other markup — `<em>` carries its own italic rendering, which is why no stylesheet is needed for a page that has none.
4. Run the test file again and confirm all four cases pass.

Run: `npx vitest run src/pages/HomePage.test.jsx`
Expected: PASS — 4 passed (footer line rendered, EM element, rendered exactly once with the 'All Items' heading intact, and rendered under StaticRouter).
5. Run the linter over the changed files.

Run: `npm run lint`
Expected: exit 0, no errors or warnings referencing src/pages/HomePage.jsx or src/pages/HomePage.test.jsx.
6. Commit the change.

```bash
git add src/pages/HomePage.jsx src/pages/HomePage.test.jsx
git commit -m "feat: add Dark Factory footer line to home page"
```

**Verification:** `npx vitest run src/pages/HomePage.test.jsx` passes 4/4 and `npm run lint` is clean; `git show --stat HEAD` lists only src/pages/HomePage.jsx and src/pages/HomePage.test.jsx.
