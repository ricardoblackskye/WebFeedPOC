# Plan: Dark Factory Test Issue

Story: #232
Issue: [#232](https://github.com/ricardoblackskye/webfeedpoc/issues/232)

## Goal

A single, deliberately minimal UI change: render one italic footer line reading 'Built by the Dark Factory - by the Developer Agent' beneath the product grid that the home page composes. The line is added to src/components/ProductList.jsx (the component src/pages/HomePage.jsx imports and renders for the paginated product list), styled by one new rule in its co-located src/components/ProductList.css, and pinned by four Vitest/@testing-library assertions added to src/components/ProductList.test.jsx. Italics are expressed with the semantic `<em>` element so the requirement is assertable in jsdom (CSS files are not applied by jsdom). No props, routes, state, data flow, or dependencies change.

## Approach

The story asks for exactly one visible change: a footer line reading 'Built by the Dark Factory - by the Developer Agent', in italics, on the home page, and nothing else. The site already has a global footer, but it lives in the App shell (src/App.jsx), which the evidence shows renders an `<Outlet/> and therefore renders on every route - anything added there would also appear on /products/:slug, /category/:categoryName and /architecture, which the story's 'No other changes' rules out. The home page's own content surface is src/pages/HomePage.jsx (the '/' index route), which per the evidence imports and renders 'ProductList' for the paginated products ('import ProductList from ../components/ProductList' and '<ProductList products={paginatedProducts} onAddToCart={addToCart} />`'). That component is therefore the container the new line belongs to, and it is the file this plan modifies: src/components/ProductList.jsx.

The implementation is intentionally tiny. A '`<p className="product-list-footer">' wrapping an '<em>' with the exact story string is added as the last child of the component's root element, after the existing 'products.map(...)' ProductCard output, so it renders beneath the grid. '<em>`' is used rather than a span with an inline style because it is the semantic italic element: it makes the italic requirement part of the markup and directly assertable in jsdom, whereas a CSS-only italic could not be verified by the test runner. src/components/ProductList.css receives one new '.product-list-footer' rule (margin, centering, and a redundant font-style: italic so the line stays italic even if the markup is later changed to a non-em element). No existing rule, prop, or rendered element is altered.

No data flow, routing, state, prop or dependency changes are made: ProductList keeps the same props HomePage already passes ('products', 'onAddToCart'), no npm package is added, and no other component is touched. The work is done test-first with Vitest and @testing-library/react, following the pattern already used by src/components/Cart.test.jsx (jsdom, 'render', 'screen', 'expect', 'vi.fn()'). Four assertions pin the behaviour: the exact copy, the italic element, the line still rendering when the product array is empty, and existing product cards still rendering alongside it.

Review focus - the inputs and conditions this change will meet that the story does not mention, most likely first: (1) home page with zero products - HomePage only mounts ProductList when paginatedProducts.length > 0, so on an empty catalogue the line is not shown; the component-level test pins that the line renders whenever ProductList itself is mounted with products={[]}, so the gap is visible and bounded rather than silent. (2) Copy drift - the exact string contains a spaced hyphen and the words 'by the Developer Agent'; the test uses the literal string, so any rewording fails the build. (3) Typography - the hyphen must not be replaced by an en/em dash or a non-breaking space; the literal assertion prevents that. (4) Other consumers of ProductList - the line renders wherever ProductList is mounted (for example a category route); this is accepted because the story's 'No other changes' constrains the code we touch, and no shared markup or styling is modified. (5) Assistive technology - the addition is a plain paragraph of text inside an `<em>`, adding no heading, landmark, or focusable element to the accessibility tree.

## Tasks

### 1. Add the italic Dark Factory footer line to the home page product list

**Objective:** Render the exact line 'Built by the Dark Factory - by the Developer Agent' in italics beneath the product grid rendered by ProductList on the home page, changing nothing else about the component, its props, or the rest of the site.

**Files:** `src/components/ProductList.jsx`, `src/components/ProductList.css`, `src/components/ProductList.test.jsx`

**Steps:**

1. Write the failing tests. Append this block to src/components/ProductList.test.jsx, which already imports ProductList from './ProductList' and the Vitest/Testing-Library helpers (render, screen, expect, vi, describe, it). Reuse the file's existing product fixture if it has one; otherwise add the 'products' constant shown here. Keep the assertions exactly as written - the string literal is the contract.

const products = [
  { id: '1', name: 'Oak Sideboard', price: 250, image: '`https://example.com/a.jpg'` },
]

describe('ProductList - Dark Factory footer line', () => {
  it('renders the Dark Factory footer line with the exact story text', () => {
    render(`<ProductList products={products} onAddToCart={vi.fn()} />`)
    expect(
      screen.getByText('Built by the Dark Factory - by the Developer Agent')
    ).toBeDefined()
  })

  it('renders the footer line in an italic `<em>` element', () => {
    render(`<ProductList products={products} onAddToCart={vi.fn()} />`)
    const line = screen.getByText('Built by the Dark Factory - by the Developer Agent')
    expect(line.tagName).toBe('EM')
  })

  it('renders the footer line when the product list is empty', () => {
    render(`<ProductList products={[]} onAddToCart={vi.fn()} />`)
    expect(
      screen.getByText('Built by the Dark Factory - by the Developer Agent')
    ).toBeDefined()
  })

  it('still renders every product card alongside the footer line', () => {
    render(`<ProductList products={products} onAddToCart={vi.fn()} />`)
    expect(screen.getByText('Oak Sideboard')).toBeDefined()
    expect(
      screen.getByText('Built by the Dark Factory - by the Developer Agent')
    ).toBeDefined()
  })
})
2. Run the new tests and confirm they fail for the right reason: npx vitest run src/components/ProductList.test.jsx. Expected: 4 failures, each 'Unable to find an element with the text: Built by the Dark Factory - by the Developer Agent' (the empty-list case fails the same way; the product-card case fails on the footer assertion only).
3. Implement the markup in src/components/ProductList.jsx. Add this paragraph as the LAST child inside the component's root element, immediately after the existing products.map(...) ProductCard output, and change nothing else in the file:

`<p className="product-list-footer">`
  `<em>Built by the Dark Factory - by the Developer Agent</em>`
`</p>`

The `<em>` element is what makes the line italic; it is also what the second test asserts.
4. Style the line in src/components/ProductList.css. Append this rule and do not modify any existing rule:

.product-list-footer {
  margin-top: 1.5rem;
  text-align: center;
  font-style: italic;
}
5. Run the new tests and confirm they pass: npx vitest run src/components/ProductList.test.jsx. Expected: 4 passed.
6. Run the full suite and the linter to confirm nothing else regressed: npx vitest run && npm run lint. Expected: all suites green (no new failures) and eslint reports no new errors.
7. Commit the change:

git add src/components/ProductList.jsx src/components/ProductList.css src/components/ProductList.test.jsx
git commit -m "feat: add Dark Factory footer line to home page product list"

**Verification:** npx vitest run src/components/ProductList.test.jsx reports 4 passing tests covering the exact copy, the `<em>` (italic) element, the empty-products case, and unchanged product-card rendering; a full npx vitest run shows no new failures and npm run lint is clean.
